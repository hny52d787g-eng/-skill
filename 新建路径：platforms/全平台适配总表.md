# NovelForge v1.1｜全平台适配总表

## 目标平台与推荐用法

| 平台 | 推荐方式 | 交付文件 | 关键限制 |
|---|---|---|---|
| DeepSeek 网页版/APP | 项目指令或新对话粘贴核心指令；分阶段上传/粘贴状态文件 | `platforms/adapters/DeepSeek_使用包.md` | 不把 API 文件接口等同于聊天端知识库；以当前客户端实际上传能力为准 |
| DeepSeek Harness 桌面端 | 作为项目工作区文件；可按其原生插件/技能机制另行包装 | `platforms/adapters/DeepSeek_Harness_使用包.md` | 原生插件规范随版本变化，需按官方最新说明和本地实际界面验证 |
| WorkBuddy | 优先安装原生 Skill 包；也可上传整个项目文件夹并引用模块 | `workbuddy_skill/` 与 `platforms/adapters/WorkBuddy_使用包.md` | Skill 包结构与功能以当前版本导入结果为准；首次使用需进行验收测试 |
| 豆包 | 创建/配置自定义智能体时使用角色说明；把模块与模板作为知识资料或按需粘贴 | `platforms/adapters/豆包_使用包.md` | 智能体配置入口、知识资料类型与限制以账号当前版本为准 |
| 通义千问/千问 | 普通聊天使用提示词版；若使用阿里云百炼智能体，则配置系统提示词并连接知识库 | `platforms/adapters/千问_使用包.md` | “千问聊天产品”和“百炼智能体应用”是不同产品形态，不能混为一谈 |
| 通用知识库（ima/其他知识库/RAG） | 按主题拆分、分块、添加元数据；核心规则放在智能体系统指令而非只放知识库 | `knowledge_base/` | 知识库通常用于检索资料，不一定能自动执行 Skill 流程 |

## 核心设计原则
1. **规则与资料分离**：系统指令负责流程与行为；知识库负责可检索的模板、规则和项目事实。
2. **短指令优先**：平台有上下文或指令长度限制时，核心指令保持精简，模块按需加载。
3. **项目状态外置**：每章生成章节记录卡；定期保存项目快照。
4. **平台能力不夸大**：只有完成实际测试的平台才可在商品页标记“已测试”。
5. **不承诺一键通用安装**：WorkBuddy 原生 Skill、豆包智能体、百炼智能体、聊天端提示词和知识库是不同机制。
